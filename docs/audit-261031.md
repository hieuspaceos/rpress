# Audit tổng thể rpress — 2026-10-31

Phạm vi: `src/` (~54k LOC Rust), `src/admin/` + `src/admin/bridge/`, `src/db/`,
`src/render*/`, `tests/`, `scripts/`, `.github/`, `build.rs`, `install.sh`,
`sites/`, `plans/`, `docs/`. Ba luồng audit song song: code quality/kiến trúc,
bảo mật, tests/hygiene. Mọi phát hiện có file:line.

## Đánh giá chung

Codebase chất lượng tốt, kiến trúc rõ ràng và khớp `docs/architecture.md` /
`code-standards.md` ở mức module. Điểm mạnh đã xác nhận:

- `sqldump.rs` là streaming parser đúng chuẩn (4MB BufReader, statement-level).
- `db::conn` pragmas + `BEGIN IMMEDIATE` + busy_timeout đúng cho WAL.
- Đường public (`admin/serve.rs`) harden kỹ: path allowlist (91-95),
  `safe_read_under` symlink guard (450-467), canonical-301, rate-limit
  render-miss, `SameSite=Lax` + bearer-token fence cho bridge.
- Login trên trung bình: `/24`-keyed capped `login_hits`, `pending_2fa` cap,
  timing-equalization (`admin/auth.rs:105-131, 165-175`).
- Session sweep đã có (`sweep_sessions`, `mod.rs:615`).

Vấn đề hệ thống: **kỷ luật áp cho đường public chưa lan sang `/admin/*`** —
blocking I/O trên runtime, nuốt lỗi write, và 2 stored XSS xác nhận.

## 1. Bảo mật — Critical/High

### 1.1 Stored XSS: tên comment trong `alt` single-quoted — HIGH

- Source: `intake.rs:216-345` — `/intake/comment` unauthenticated
  (rate-limit 10/5min/IP + honeypot), `wc_name` lưu verbatim.
- Sink: `render_post.rs:648-662` — `comment_html()` đặt `esc(&c.author)`
  vào `alt='{author}'`; `esc()` (`html_decode.rs:43-52`) chỉ escape
  `& < > "` — **không escape `'`**.
- Hậu quả: `'` thoát attribute → inject markup vào trang public **và vào
  write-back cache** (persist). Khi `comment_moderation=0` (default) payload
  chạy ngay; khi moderation bật, moderator approve là kích hoạt.
- Escalation: admin pages nhúng `s.csrf` trong DOM (`admin/posts.rs:1435`) —
  script same-origin đánh cắp CSRF token, thực hiện mọi admin action
  (tắt 2FA, tạo user, sửa content) khi admin duyệt site.
- Fix: dùng `esc_attr` (hoặc double-quoted attr + `esc`) tại mọi attribute
  interpolation; grep toàn cục `='{` để tìm site tương tự; cân nhắc cấm
  quote trong tên comment tại intake.

### 1.2 Stored XSS: SEO focus keyword → innerHTML — HIGH

- Source: `post_meta.rank_math_focus_keyword` (`db/posts.rs:903-904`),
  editor-controllable.
- Fragment: `admin/rankmath.rs:45-53` — `seo_inner()` đặt `a.keyword` raw
  (không `esc()`), trong khi các sibling đều escape.
- Sink: `admin/posts.rs:563` — `td.innerHTML = fetch('/admin/seo/cell/'+id)`.
- Hậu quả: editor (không có quyền users/app-pass) gài payload → admin mở
  `/admin/posts` → đánh cắp CSRF → **privilege escalation editor→admin**.
- Fix: `esc(&a.keyword)` trong `seo_inner`; audit mọi site
  `innerHTML = <fetch response>`.

### 1.3 Backup-code 2FA ~32-bit entropy — MEDIUM

- `auth.rs:153-168`: 4 bytes rand → `xxxx-xxxx` = 2^32 code; lưu SHA-256
  trần, không salt.
- `rpress.db` (tải được qua admin backup) bị lộ → brute-force 2^32 SHA-256
  trong vài giây → bypass 2FA. Online path chặn bởi 5-fail cap, offline không.
- Fix: ≥128 bit entropy/code (2×u64 hoặc base32 16 bytes) và/hoặc lưu
  argon2/bcrypt.
- [ĐÃ FIX 261031] base32 16 bytes = 128-bit `xxxxx-…`; verify normalize
  dash/whitespace/case. **Hệ quả:** mọi backup code cũ (`xxxx-xxxx`,
  sha256 không-normalize) không còn verify được — user giữ code cũ phải
  regen (`/admin/profile/2fa`) hoặc admin reset bằng `rpress user passwd`.

### 1.4 systemd unit chạy root — MEDIUM

- `install.sh:120-145`: unit thiếu `User=` → rpress + SQLite + `php -S`
  bridge + bwrap children đều uid 0. Hardening khác (ProtectSystem=strict,
  ProtectHome, NoNewPrivileges) vẫn đúng nhưng root sở hữu tất cả.
- Fix: tạo system user `rpress` (`User=rpress`, chown `${ROOT}/work`) hoặc
  `DynamicUser=yes` + `StateDirectory`; giữ IPAddressAllow/Deny.

### 1.5 Login `pwd.trim()` mismatch — LOW

- `admin/auth.rs:105-108` trim password trước verify; `auth.rs:7-30`
  (`add_user`/`set_password`) hash verbatim → account có whitespace password
  lockout vĩnh viễn, decoy-hash path che dấu chẩn đoán.
- Fix: bỏ trim password (trim email vẫn OK).

Đã rà và sạch: SQLi (mọi `format!` vào SQL đều qua placeholder; ngoại lệ
`site_deploy` chỉ là tên bảng/cột literal), path traversal (`safe_read_under`),
upload type gates, bridge token fence + sandbox, CSRF, cookie flags,
open-redirect gates, header rewriting.

## 2. Code quality / Concurrency — Critical

### 2.1 Blocking rusqlite trên async runtime (C1)

Đường public đã offload đúng (`serve.rs:43-47, 256-262`) nhưng `/admin/*`
không:

- `admin/posts.rs:580-591` `trash_post` chạy `crud::set_post_status` inline —
  ngay dưới `bulk_posts` (613-638) lại `spawn_blocking` đúng cho cùng việc.
- `admin/posts.rs:48-56` `section`, `1585-1603` `save_post` — inline.
- `admin/comments.rs`, `users.rs`, `menus.rs`, `tax.rs`, `widgets.rs`,
  `settings.rs`: **zero `spawn_blocking`** — ~4.700 LOC CRUD blocking trên
  runtime.
- `admin/auth.rs:139-158`: argon2 (~50-100ms CPU) inline; `dummy_hash()`
  gấp đôi block.
- `admin/serve.rs:163`: `db::conn` + `lang::config` inline trong
  `public_page` trước miss-path.
- `admin/mod.rs:384-395`: minute tick gọi `serve::publish_due`,
  `sweep_sessions` (1 conn/site + DELETE), `bridge::reap` (kill/wait
  blocking I/O) trên async task.
- `SiteCtx::settings()` (`mod.rs:97-116`) mở conn sync — được gọi từ
  `site_url`/`asset_origin`/`allowed_origins` trong async paths.

Fix: `spawn_blocking` uniform cho mọi `db::`/`crud::`/`udb::` call; thêm rule
grep vào `check-layers.sh` flag `crud::`/`udb::` ngoài `spawn_blocking` trong
`admin/*.rs`.

### 2.2 Nuốt lỗi write — `let _ =` trên DB mutations (C2)

- `admin/posts.rs:587`: trash fail vẫn regen + redirect success (xóa cache).
- `admin/users.rs:1092-1096`: delete user fail vẫn xóa sessions/app-passes.
- `admin/users.rs:1173-1175, 1242, 1313, 1334, 1345, 1354`: đổi role,
  bật/tắt TOTP, revoke app-pass — UI báo success khi DB fail. TOTP silent
  no-op là hazard bảo mật-logic.
- `admin/mod.rs:620`: `sessions__delete_expired` fail → token sống trong
  backup.
- Tổng 78 `let _ =` trong `src/admin/`; một số (file cleanup) chấp nhận
  được, phần DB mutation cần `?` + 500 hoặc tối thiểu `eprintln!`.

## 4. Maintainability — Medium

- `import.rs` 2.941 LOC — 1.300 LOC `widget_*`/`gdlr_*`/`media_image_html`

  intake + generate API).
- `db/posts.rs` 1.638 LOC trộn admin list queries + translation mutation +
  `setting_value` reads (75, 722).
- `render.rs:990` fallback `theme/traveltour` literal — đã có `// gate-allow:
  legacy fallback` nên là intentional, không phải vi phạm ngẫu nhiên; vẫn
  là tech-debt rule 9 ("themes are data") — thay bằng
  `ThemeDef.fallback_dir` khi nào retire legacy sites. Ưu tiên thấp.
- Error handling ad-hoc: `unwrap_or_default()`/`flatten()` trên `query_row`
  trong render paths (`render.rs:495-501`, `generate.rs:477-481`,
  `site_data.rs` meta loops) → DB lỗi render thiếu meta thay vì 500.
  53 files anyhow, 0 thiserror; ~201 `unwrap()` hầu hết LazyLock
  regex/test — low risk.
- `admin/comments.rs:21` local `esc_attr` shadow tên shared helper → đổi
  tên `esc_attr_lines`.
- Dead code giữ bằng `#[allow(dead_code)]` ngược rule 8: ~10 fields trong
  `plugins/mod.rs`, `tourmaster/schema.rs` ×3, `bridge/mod.rs` ×3,
  `bridge/pull.rs` ×1; `#[allow(unused_imports)]` ở `posts.rs:1`,
  `render.rs:3`, `generate.rs:3`, `auth.rs:1`, `util.rs:8`.
- `db/mod.rs:77-79` `conn_write` mang `#[allow(dead_code)]` **sai** — vẫn
  được gọi tại `db/posts.rs:1049` (`save_post`, đường write-transaction
  A15). Chỉ cần bỏ attribute, KHÔNG xóa hàm.
- Hai convention CSRF trong `posts.rs` (`check_csrf` vs `ct_eq` tay, 596-598).
- `main.rs` flag defaults (`tour_base "voyage"`, `site_url localhost:8400`)
  duplicate qua 3 `#[arg]` blocks → clap flatten struct.
